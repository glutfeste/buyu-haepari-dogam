# 채팅 집필 시스템

ChatGPT에서 집필을 지시하고 이 저장소의 `main`에 원고와 진행 상태를 저장한다. ChatGPT는 자료 읽기, 장면 설계, 본문 작성, 검토, 수정을 수행한다. `scripts/novel_workflow.py`는 단계 순서, 파일 버전, 근거 인용, 확정 승인을 검사하고 GitHub 저장 묶음을 만든다.

작업 규칙의 기준 문서는 [AGENTS.md](../AGENTS.md)와 [집필 원칙](../원고/집필%20원칙.md)이다. 이 문서는 설치된 코드의 사용법과 저장 계약을 설명한다. 개인 응답 지침은 ChatGPT 프로젝트 설정에서 관리한다.

## ChatGPT에서 시작하기

ChatGPT의 프로젝트 설정에 [프로젝트 연결문](프로젝트연결.txt)을 등록하고 GitHub 앱을 사용한다. 이어서 아래와 같이 요청한다.

| 채팅 요청 | 수행 내용 |
| --- | --- |
| `25화 초안부터 검토와 수정까지 진행해.` | 지정 자료 확인, 설계, 집필, 검토, 수정본 저장 |
| `12화를 이 방향으로 개고해: …` | 현재 원고와 지정 범위 확인, 개고 설계, 수정본과 검토 결과 저장 |
| `이어서 해.` | 활성 작업 또는 마지막 정지 작업의 저장 상태를 읽고 다음 단계 실행 |
| `여기까지 저장해.` | 현재 단계의 부분 결과와 체크포인트를 같은 커밋에 저장 |
| `인물 상태와 복선을 정리해.` | 실제 원문 인용과 파일 버전을 붙여 추적 자료 갱신 |
| `이 수정본으로 확정해.` | 승인된 수정본의 버전을 확인하고 `원고/본문/`에 반영 |
| `저장 상태 보여줘.` | 원격 체크포인트, 원고 위치, 다음 작업 표시 |

집필 시스템 설치 시 기존 본문 01~24화의 경로와 blob SHA를 원고 목록에 등록했다. 원고 목록은 해당 시점의 파일 색인이다. 작업 시작 때 현재 원격 목록과 버전을 다시 확인한다. 작품 내용의 판단과 집필은 지정 자료의 실제 열람을 거쳐 수행한다.

## 저장되는 것

| 경로 | 역할 |
| --- | --- |
| `진행상태.json` | 활성 작업, 단계, 자료 버전, 부분 결과, 이어서 할 작업 |
| `원고목록.json` | 기존 원고의 파일 경로와 확인 시점의 버전 |
| `인물·복선.json` | 원문 인용과 출처가 붙은 인물 상태 및 서사 추적 자료 |
| `작업/<작업ID>/context.md` | 지정 자료의 확인 범위와 이번 작업에 적용할 근거 |
| `작업/<작업ID>/blueprint.md` | 이번 화의 목표·장면·시점·인과·지식 시점·복선 계획 |
| `작업/<작업ID>/draft.md` | 초안 또는 해당 단계의 부분 원고 |
| `작업/<작업ID>/review.md` | 원고 위치, 적용 규칙, 판단 근거, 수정 방향이 담긴 검토 |
| `작업/<작업ID>/revision.md` | 검토 지시를 반영한 수정본 |
| `../원고/본문/` | 작가가 확정한 본문을 반영하는 위치 |

각 작업의 이전 버전은 Git 커밋과 diff로 확인한다. 작업 파일은 현재 단계의 결과를 담는다. 인물·복선 기록은 출처가 연결된 파생 자료이며, 세계관과 작품 전개의 기준은 기존 설정·이야기·원고 문서가 담당한다.

## 채팅 요청을 실행하는 순서

1. 현재 요청의 질문과 실행 항목을 순서대로 확인한다. 질문에 직접 답하고 요청한 작업을 수행한다. 요청의 원문과 범위는 작업의 `request`에 기록한다.
2. GitHub에서 `main`의 HEAD와 tree, `진행상태.json`, `인물·복선.json`, 기존 기준 문서를 읽는다. 긴 문서는 범위를 나누어 끝까지 열람한다. `원고/집필 원칙.md`에 따른 지정 자료 범위를 재귀적으로 목록화하고 완독한다.
3. 이번 작업의 파일 경로와 blob SHA를 고정한다. 실제 읽은 자료와 열람 범위를 기록한다. 완독 기록은 범위 추적 자료다. 새 판단에 필요한 원문은 해당 파일에서 읽는다.
4. 아래 저장 계약에 맞춰 `start`와 단계별 `advance`를 실행한다. ChatGPT가 각 단계의 내용을 작성하고 Python 코드가 저장 조건을 검사한다. 여러 화 요청은 지정 순서대로 작업을 생성하고 각 화의 상태를 저장한다.
5. 의미, 범위, 조건, 강도, 기존 피드백을 유지하며 적용 가능한 지침 전체를 대조한다. 원고 검토에는 사실·인과·시점·지식·문체·표현·복선의 근거를 구체적으로 적는다. 수정 지시는 해당 검토본의 SHA와 함께 기록한다.
6. GitHub에 결과와 상태를 같은 커밋으로 저장하고 다시 읽어 확인한다. 작가의 확정 지시가 가리키는 수정본을 `finalize`로 반영한다.

한 채팅 요청의 작업은 그 응답에서 수행한다. 다음 요청의 `이어서`는 마지막으로 저장된 결과를 읽고 재개한다. 부분 원고의 보존 지점은 `partial` 저장을 마친 시점이다.

## 코드 실행과 GitHub 저장 계약

Python 3.10 이상에서 표준 라이브러리로 실행한다. ChatGPT는 연결된 GitHub 도구로 원격 파일을 읽고, 작업 환경에서 아래 명령을 실행한 뒤, 같은 GitHub 도구로 저장한다.

```text
python scripts/novel_workflow.py status snapshot.json
python scripts/novel_workflow.py prepare snapshot.json --event event.json --output prepared.json
python -m unittest discover -s scripts -p test_novel_workflow.py -v
```

`snapshot.json`은 현재 `repository`, `branch`, `head`, `tree`와 `files`를 담는다. `files`는 `{경로: {sha, content}}` 형식이다. `sha`는 GitHub가 반환한 blob SHA이며 `content`는 정확한 UTF-8 원문이다. 버전 검사 단계에는 SHA를, 본문 검사 단계에는 전체 원문을 제공한다. 새 본문 경로는 같은 HEAD의 완전한 디렉터리 목록 또는 해당 경로 조회 결과로 생성 가능 상태를 확인하고 `verified_new_paths`에 넣는다.

`event.json`은 `event_id`, `expected_revision`, `op`와 작업별 값을 담는다. `event_id`는 저장 재시도에서 동일하게 유지한다. 동일 ID의 재시도는 동일한 요청 내용을 사용한다.

| op | 추가 입력 |
| --- | --- |
| `start` | `job_id`, `chapter`, `request`, `source_paths` |
| `advance` | 현재 `stage`, 해당 단계의 전체 `content` |
| `partial` | 현재 `stage`, 그 시점까지의 전체 `content` |
| `pause` | 활성 작업을 정지하고 재개 대상으로 기록 |
| `activate` | 재개할 `job_id` |
| `refresh` | 현재 자료로 확인 단계를 다시 시작; `source_paths`로 범위 지정 가능 |
| `annotate` | `ledger.characters`, `ledger.threads` |
| `finalize` | `target`, `target_expected_sha`, `approval`; 필요한 `ledger` |

자료 확인 단계를 완료할 때 `read_attestation`에 `reader: "ChatGPT"`와 실제 완독한 `complete_paths` 전체를 넣는다. 코드는 등록 범위와 전달된 원문 바이트를 검사한다. 열람 기록의 사실성은 작업을 수행한 ChatGPT가 책임진다.

수정 단계를 완료할 때 `review_decision`에 수정 지시 `instruction`과 적용한 `review_sha`를 넣는다. 확정 시 `approval`은 `actor: "user"`, 작가의 실제 확정 지시 `instruction`, 승인 대상 `revision_sha`를 담는다. 기존 본문을 갱신할 때 `target_expected_sha`에 현재 blob SHA를 넣고, 확인한 새 경로를 생성할 때 JSON `null`을 넣는다.

추적 자료의 각 항목은 `id`, `value`, `kind`, `evidence`를 담는다. `kind`는 실제 사건 `observed` 또는 전개 계획 `planned`다. `evidence`는 원본 `path`, `sha`, 실제 원문 `quote`를 담는다. 한 인물의 시점별 상태와 각 복선은 서로 구분되는 ID로 기록한다. 코드는 버전과 인용문 포함 여부를 검사한다. 사건 해석과 문학적 판단은 원문을 읽은 ChatGPT의 검토와 작가의 판단으로 확정한다.

`prepared.json`의 결과는 저장 준비 상태다. 아래 GitHub 호출이 실제 원격 저장을 수행한다.

1. `create_tree(repository_full_name, tree_elements, base_tree_sha)`에 준비된 묶음을 전달한다.
2. `create_commit(repository_full_name, message, tree_sha, parent_sha=expected_head)`로 커밋을 만든다.
3. `update_ref(repository_full_name, branch_name="main", sha=새커밋, expected_sha=expected_head)`로 반영한다. 기본 fast-forward 검사를 유지한다.
4. 반환된 성공 여부를 확인하고 새 커밋의 상태 파일과 산출물을 `fetch_file(ref=새커밋)`로 다시 읽는다. HEAD도 확인한 뒤 저장 결과를 알린다.

HEAD 또는 자료 버전이 변경되면 현재 상태를 다시 읽어 작업을 정렬한다. 출처가 바뀐 작업은 `refresh`를 통해 자료 확인부터 재개한다. 같은 저장 요청의 재시도 결과 `already_saved`는 해당 event가 저장됐다는 상태 파일 기록을 나타낸다.
